# LogHive — frontend

Интерфейс сервиса сбора логов на React + Vite. Работает с backend LogHive (ASP.NET Core)
по HTTP API с JWT-авторизацией.

## Запуск

1. Запустите backend LogHive и PostgreSQL.
2. Установите Node.js (LTS), откройте папку frontend в терминале и выполните:
   ```bash
   npm install
   npm run dev
   ```
3. Откройте http://localhost:5173 и войдите под пользователем `root`.

По умолчанию запросы `/api/...` проксируются на `http://localhost:5300` (адрес из документации API).
Если backend запущен на другом адресе, создайте файл `.env.local` рядом с `package.json`,
впишите нужный адрес и перезапустите `npm run dev`:
```
VITE_API_TARGET=http://localhost:5300
```
Для профиля `https` укажите `VITE_API_TARGET=https://localhost:7205` (адрес из документации;
сертификат разработчика не проверяется).

Чтобы frontend обращался к backend напрямую, а не через прокси Vite, задайте `VITE_API_URL`
(например, `https://loghive.example.com`). Тогда на backend должен быть включён CORS для адреса frontend.

## Как это устроено

- **Вход:** `POST /api/auth/login` (`username`, `password`) возвращает JWT. Токен хранится в
  `localStorage`, пароль нигде не сохраняется. При запуске токен проверяется через `GET /api/auth/me`.
- **Запросы:** все запросы идут через `src/api.js`, он сам добавляет `Authorization: Bearer ...`.
  Ответ `401` удаляет токен и возвращает на страницу входа, `403`, `404`, `400` и `5xx`
  показываются понятными сообщениями.
- **Выход:** отдельного endpoint нет, токен просто удаляется.

Используются endpoint: `POST /api/auth/login`, `GET /api/auth/me`, `GET /api/analytics/summary`,
`GET /api/analytics/timeline`, `GET /api/issues`, `GET /api/issues/{id}/events`,
`PATCH /api/issues/{id}/resolve`. Дополнительно, если он есть в backend, запрашивается
`GET /api/issues/{id}`: без него карточка ошибки строится по данным списка.

Список ошибок принимается в обоих видах: массивом (как в документации) и объектом `{ total, items }`.

## Экраны

- **Вход:** логин, пароль, сообщение об ошибке.
- **Ошибки (главная):** карточки «Всего событий», «Всего Issues», «Нерешённые», «Решённые»,
  график событий, фильтры периода, уровня и статуса, поиск, таблица с пагинацией.
- **Карточка ошибки:** ID, название, уровень, статус, количество событий, первое и последнее
  появление, график за неделю, стектрейс (если есть), история событий, кнопка «Решить».

## Ограничения

- **Вернуть решённую ошибку в актуальные нельзя** — в backend есть только `resolve`.
- **График ошибки** строится из событий (backend не отдаёт его отдельно): берутся последние
  1000 событий за 7 дней. Если их больше, под графиком это указано.

## Структура

- `src/main.jsx` — точка входа, проверка сессии.
- `src/Login.jsx` — страница входа.
- `src/api.js` — HTTP-клиент: токен, заголовки, обработка статусов.
- `src/auth.js` — вход, текущий пользователь, выход.
- `src/normalize.js` — приведение ответов backend к единому виду.
- `src/format.js` — форматирование дат и чисел, группировка событий по дням.
- `src/App.jsx` — список ошибок и карточка ошибки.
- `src/styles.css` — оформление и темы.
