# Правила доступа LogHive

## 1. Роли

| Роль | Кто | Разрешённые действия |
|---|---|---|
| Приложение-отправитель | Любое приложение проекта (по API-ключу) | Только отправка ошибок в свой проект: `POST /api/events`. Читать данные нельзя |
| Наблюдатель | Участник команды проекта | Просмотр групп ошибок, карточек и статистики своих проектов |
| Разработчик | Участник команды проекта | Всё, что наблюдатель, плюс смена статуса группы (решена / открыть заново) в своих проектах |
| Администратор LogHive | Владелец сервиса | Создание проектов, выдача и перевыпуск API-ключей, назначение пользователей на проекты |
| Администратор сервера | Инженер эксплуатации | Подключение к серверу, развёртывание, резервные копии, мониторинг (см. раздел 3) |

## 2. Данные

Объект, который один пользователь не должен видеть у другого: **ошибки и события чужого проекта**. Стектрейсы содержат имена классов, пути, а иногда и данные пользователей или токены.

Правило: пользователь видит только проекты, на которые назначен. Запрос чужой группы ошибок (`GET /api/issues/{id}`) возвращает 404, а не 403, чтобы не раскрывать, что такая группа существует.

Проверка: пользователь проекта A запрашивает группу ошибок проекта B и список проектов. Ожидаем 404 и список без проекта B.

## 3. Администрирование

| Кто | Что делает | Права |
|---|---|---|
| Икромжонов Ш. (инфраструктура) | Сервер, сеть, Docker, мониторинг | SSH по ключу, группа `docker`, `sudo` для администрирования; Grafana — Admin |
| Жидкова В. (автоматизация, данные) | Сценарий развёртывания, резервные копии, восстановление | SSH по ключу, запуск скриптов развёртывания и копий, чтение БД; без root; Grafana — Editor |
| Иванова А. (документация) | Инструкции и регламенты | Без доступа к серверу; Grafana — Viewer, Wiki — редактор |

Общие правила:
- подключение только через WireGuard, из интернета сервер закрыт;
- вход по SSH только по ключу, пароли и вход под root отключены;
- учётные записи персональные, общих не создаём;
- уволенный или выбывший участник теряет доступ в тот же день: удаляем его ключ SSH и пользователя в Grafana.

## 4. Секреты

| Секрет | Как передаётся и хранится | Действия при утечке |
|---|---|---|
| API-ключ проекта | Показывается один раз при создании, в БД хранится только хеш. Передаётся владельцу проекта лично или через менеджер паролей, не в чат и не в репозиторий | Перевыпустить ключ (старый перестаёт работать сразу), проверить события проекта за период утечки, удалить подозрительные |
| Пароль PostgreSQL | Хранится в файле `.env` на сервере с правами `600`, в репозитории только `.env.example`. В пайплайне Drone передаётся через секреты Drone | Сменить пароль в БД, обновить `.env`, перезапустить сервисы, проверить журнал подключений. Если секрет попал в git, считаем его скомпрометированным: удаления коммита недостаточно, меняем пароль |
