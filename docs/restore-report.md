# Отчёт об учебном восстановлении БД LogHive

Дата: 27.11.2026
Требование: N-03 (RPO ≤ 1 часа, RTO ≤ 30 минут)
Ответственные: Жидкова В. (восстановление), Иванова А. (копирование)

## Что копируется, как часто и куда

| Что | Как | Как часто | Куда | Сколько храним |
|---|---|---|---|---|
| БД LogHive (PostgreSQL на ВМ 1) | `pg_dump` в контейнере `loghive-db`, сжатие gzip | каждый час (`backup.sh hourly`) | ВМ 3, `/home/user/backups/hourly` | 3 последние копии |
| То же | то же | раз в сутки (`backup.sh daily`) | ВМ 3, `/home/user/backups/daily` | 7 копий |

ВМ 3 сама заходит на ВМ 1 по SSH-ключу и забирает копию. ВМ 1 доступа к копиям не имеет и удалить их не может.

## Сценарий учения

Сбой: потеря данных БД на ВМ 1. Нужно поднять базу из последней копии с ВМ 3.

Чтобы не останавливать рабочий стенд перед защитой, копия восстанавливалась в отдельный проверочный контейнер на ВМ 3. Рабочий том на ВМ 1 не удалялся.

## Команды (ВМ 3)

```bash
# 1. Снять свежую копию
./backup/backup.sh hourly

# 2. Восстановить последнюю копию в проверочный контейнер и посчитать строки
time ./backup/restore-test.sh
```

Что делает `restore-test.sh`:
1. Поднимает контейнер `postgres:18-alpine` (та же версия, что на ВМ 1).
2. Заливает в него последнюю копию.
3. Считает строки в таблицах `users`, `issues`, `events`, `notification_outbox`.
4. Удаляет контейнер.

## Найдено и исправлено

- В расписании cron на ВМ 3 был старый путь к `backup.sh`, и часовые копии не создавались. Путь исправлен, копии идут каждый час.

## Что не проверено

- Полное восстановление с удалением тома БД на рабочей ВМ 1 не проводилось, чтобы не останавливать стенд. Это следующий шаг (раздел 6 устава).

## Восстановление на рабочей ВМ 1 (порядок для настоящей аварии)

```bash
# на ВМ 1: остановить API и поднять пустую БД
cd /home/user/LogHive && docker compose stop backend
docker compose up -d postgres

# на ВМ 3: залить последнюю копию в БД на ВМ 1
F=$(ls -1t /home/user/backups/hourly/*.sql.gz | head -n1)
gunzip -c "$F" | ssh user@192.168.71.10 "docker exec -i loghive-db psql -U loghive -d LogHiveDB"

# на ВМ 1: запустить API и проверить
docker compose up -d backend
curl -s http://localhost/api/health
```
